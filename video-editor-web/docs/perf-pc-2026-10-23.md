# Performance on the PC (2026-10-23, dev server, built-in browser)

Measured with `T.measure` / `T.seekBench` (src/adapters/dev/testKit.ts) by a test agent; raw data in
`exports/perf/results.json` (not committed). Desktop numbers say where OUR code spends time; the
phone has to be measured separately.

| Scenario | fps | frame interval p95 / max (ms) | draw p50 / max (ms) | late/held | decoders | JS heap (MB) |
|---|---|---|---|---|---|---|
| 1080p video | 60 | 16.8 / 17.0 | 0.2 / 1.1 | 0 / 0 | 1 | 21→28 |
| 4K video | 59.4 | 16.8 / 33.3 | 0.2 / 0.6 | 0 / 0 | 1 | 26→35 |
| 3 video layers (PiP) | 59.7 | 16.9 / 17.0 | 0.5 / 1.1 | 0 / 0 | 3 | 24→36 |
| 6 clips, slide 600 ms, 32 s | 60 | 16.8 / 33.4 | 0.2 / 1.4 | 0 / 0 | 3 | 27→52, back to 28 |
| 30 photos of 300 ms | 60 | 16.9 / 17.0 | 0.3 / 0.6 | 0 / 0 | 1 | 25→29 |
| 60 fps source / 360p source | 60 | 16.7 / 17.0 | 0.2 / 0.6 | 0 / 0 | 1 | ~28 |
| 5 animated texts | 60 | 16.9 / 16.9 | 0.3 / 3.6 | 0 / 0 | 1 | 25→31 |

Paused seek until the exact frame is drawn (20 seeks): 1080p with ffmpeg's default ~8 s keyframe
interval p50 67 / p95 164 ms; the same video with a keyframe every second p50 37 / p95 50 ms; 4K
p50 166 / p95 331 ms; the 6-clip sequence p50 83 / p95 264 ms.

Editing live while playing (30 edits, 50 ms apart): no stall from the edits (max 0.3 ms each).
Export: 32 s at 720p in 14.1 s, at 1080p in 15.0 s; 6 s with 3 layers in 3.4 s / 3.8 s.
Process CPU ~1-2 % of 12 cores; GPU 3D engine 1-2 % average with short peaks.

## What it means

- Our main-thread work (plan + taking frames + drawing) is under 1 ms of a 16.7 ms frame, even with
  3 layers and 4K: the architecture is not the bottleneck on a desktop.
- The one visible stall is a single dropped frame (33 ms) at a junction with a transition, with or
  without edits: the outgoing clip's decoder slot starts there. Worth a look on the phone.
- Seeks depend on the source's keyframe interval: the app's preview proxies already use 1 s
  keyframes; originals straight from the camera do not.
- No sign of a leak: the heap grows during a long run and comes back.
